## 1. Introduction to Segmentation

**Segmentation** is a memory-management technique that divides a process into **variable-sized logical units**, called *segments*. Each segment represents a meaningful part of a program, such as:

- Main program / code
- Functions or procedures
- Global data
- Stack
- Heap
- Arrays or other logical data structures

Unlike paging, which divides memory into fixed-size blocks, segmentation follows the **logical structure of a program**.

### Example

Suppose a program contains code, global variables, a heap, and a stack. Segmentation can represent these as separate segments.

```text
                Process
       +-----------------------+
       | Segment 0: Code       |
       +-----------------------+
       | Segment 1: Global data|
       +-----------------------+
       | Segment 2: Heap       |
       +-----------------------+
       | Segment 3: Stack      |
       +-----------------------+
```

These segments do not need to be equal in size, and they may be stored in different locations in physical memory.

### Key Terms

| Term | Meaning |
|---|---|
| Segment | A variable-sized logical unit of a process |
| Logical address | Address generated by the CPU; in segmentation it contains a segment number and an offset |
| Physical address | Actual location in main memory |
| Base | Starting physical address of a segment |
| Limit | Length/size of a segment, used to check whether an offset is valid |
| Offset | Position within a particular segment |

## 2. Need for Segmentation

Segmentation was designed to make memory management better reflect how programmers and programs organize information.

### 2.1 Matches the logical structure of programs

Programs naturally contain separate components such as functions, data, stack, and heap. Segmentation keeps these components logically distinct.

### 2.2 Supports protection

Different segments can have different permissions. For example:

- Code segment: read and execute
- Data segment: read and write
- Shared library segment: read and execute

This helps prevent a program from accidentally modifying code or accessing memory it should not use. Actual protection depends on the operating system and hardware configuration.

### 2.3 Supports sharing

Segments such as shared libraries or re-entrant code may be mapped into multiple processes' address spaces. This can reduce duplicated memory use.

### 2.4 Allows independent growth

Some segments, such as a stack or heap, may grow independently of other segments, subject to available memory and operating-system limits.

### 2.5 Makes program components easier to manage

Because code, data, and stack are separate logical units, the operating system can manage their placement and permissions separately.

### Advantages

- Represents the logical structure of a program.
- Supports segment-level protection and sharing.
- Segments can have different sizes.
- Individual segments can grow independently when space permits.

### Disadvantages

- Variable-sized allocation can cause **external fragmentation**.
- Finding suitable free memory may be difficult.
- Compaction may be needed in some systems to combine scattered free spaces.
- Address translation requires checking the segment number and offset.

> **Important:** Segmentation can cause external fragmentation because segments are variable-sized. Paging avoids external fragmentation in physical frame allocation because all frames have the same size, although paging can cause internal fragmentation in the final page.

## 3. Logical Segments

A logical segment is a meaningful unit of a program. Each segment has its own size and purpose.

### Common Types of Segments

| Segment | Purpose |
|---|---|
| Code / Text | Stores executable instructions |
| Data | Stores initialized global and static variables |
| BSS | Stores uninitialized global and static variables in many executable formats |
| Heap | Stores dynamically allocated memory |
| Stack | Stores function-call information, local variables, and return addresses |
| Shared library | Holds code or data shared with other processes, when mapped as a segment |

These are conceptual examples. A real system's memory layout and use of segmentation depend on the processor architecture, operating system, and executable format.

### Example of Segment Sizes

Consider a process with the following logical segments:

| Segment Number | Segment Name | Size |
|---:|---|---:|
| 0 | Code | 400 bytes |
| 1 | Data | 200 bytes |
| 2 | Heap | 300 bytes |
| 3 | Stack | 150 bytes |

The sizes differ because each segment stores a different amount of information.

### Logical Address Format

In segmentation, a logical address is represented as:

```text
        Logical Address
       +----------------+
       | Segment No.    |
       +----------------+
       | Offset         |
       +----------------+
```

It is commonly written as **(s, d)**, where:

- **s** = segment number
- **d** = offset within that segment

For example, `(2, 120)` means offset 120 within segment 2.

The offset must be less than the segment's limit. If segment 2 has a limit of 300 bytes, offset 120 is valid, but offset 300 is invalid.

## 4. Segment Table

The operating system and hardware use a **segment table** to translate logical addresses into physical addresses and to check segment bounds.

Each process has a segment table, or equivalent segmentation information, describing its segments.

### Segment Table Structure

A basic segment-table entry contains:

- **Base:** Starting physical address of the segment.
- **Limit:** Length of the segment.

```text
             Segment Table
       +---------+----------+----------+
       | Segment | Base     | Limit    |
       +---------+----------+----------+
       |    0    |  1000    |   400    |
       |    1    |  2400    |   200    |
       |    2    |  4000    |   300    |
       |    3    |  5200    |   150    |
       +---------+----------+----------+
```

The values above are illustrative.

### Meaning of Base and Limit

Suppose segment 1 has:

- Base = 2400
- Limit = 200

This means the segment begins at physical address 2400 and has a length of 200 addressable units. Its valid offsets are 0 through 199, so its physical addresses range from 2400 through 2599.

**Physical address = Base + Offset**, but only after the offset passes the limit check.

### Segment Table Base Register and Length Register

Many textbook descriptions include:

- **STBR (Segment Table Base Register):** Holds the physical starting address of the segment table.
- **STLR (Segment Table Length Register):** Indicates the number of valid segment-table entries.

Before accessing a segment-table entry, the system checks whether the segment number is valid. The exact register names and implementation vary by architecture.

## 5. Address Translation in Segmentation

Address translation converts a logical address into a physical address.

A logical address is `(s, d)`:

- `s` identifies the segment.
- `d` is the offset inside that segment.

### Translation Steps

1. The CPU generates the logical address `(s, d)`.
2. Check that `s` refers to a valid segment-table entry.
3. Read that segment's base and limit.
4. Check whether `d < limit`.
5. If valid, calculate `physical address = base + d`.
6. If the segment number or offset is invalid, the hardware raises a protection/addressing exception instead of producing a valid translated address.

### Address Translation Diagram

```text
       CPU generates (s, d)
                |
                v
       Is segment number valid?
          /             \
        No               Yes
        |                 |
        v                 v
   Exception       Read Base and Limit
                          |
                          v
                    Is d < Limit?
                     /       \
                   No         Yes
                   |           |
                   v           v
              Exception   Physical Address
                          = Base + d
                               |
                               v
                         Main Memory
```

### Numerical Example 1: Valid Address

Given the following segment table:

| Segment | Base | Limit |
|---:|---:|---:|
| 0 | 1000 | 400 |
| 1 | 2400 | 200 |
| 2 | 4000 | 300 |
| 3 | 5200 | 150 |

Translate logical address **(1, 120)**.

**Step 1:** Segment number = 1, offset = 120.

**Step 2:** From the table, segment 1 has base = 2400 and limit = 200.

**Step 3:** Check the offset:

`120 < 200` → valid.

**Step 4:** Calculate the physical address:

`Physical Address = Base + Offset`

`= 2400 + 120`

`= 2520`

**Answer: Physical address = 2520.**

### Numerical Example 2: Invalid Offset

Translate logical address **(2, 300)**.

Segment 2 has base = 4000 and limit = 300.

Check the offset:

`300 < 300` → false.

Valid offsets are 0 to 299. Therefore, **(2, 300) is invalid** and causes an addressing/protection exception. Do not calculate 4300 as a valid physical address.

### Numerical Example 3: Another Valid Address

Translate logical address **(3, 50)**.

Segment 3 has base = 5200 and limit = 150.

- Check: `50 < 150` → valid.
- Physical address = `5200 + 50 = 5250`.

**Answer: 5250.**

### Numerical Example 4: Invalid Segment Number

Using the same table, translate **(4, 10)**.

The table contains segments 0 through 3 only. Segment 4 is not a valid entry, so the address is invalid and causes an exception.

### Important Exam Points

- Always validate the segment number first.
- The offset must be **strictly less than** the limit.
- If valid, physical address = **base + offset**.
- The limit represents the segment's length, not its final offset.
- Never calculate a valid physical address for an invalid logical address.

## 6. Paging vs Segmentation

Both paging and segmentation are memory-management techniques, but they divide memory differently.

### Comparison Table

| Basis | Paging | Segmentation |
|---|---|---|
| Division | Fixed-size pages | Variable-sized logical segments |
| View | Mainly physical-memory management | Logical/programmer's view of a program |
| Unit | Page | Segment |
| Size | All pages have the same size | Segments can have different sizes |
| Logical address | Page number + offset | Segment number + offset |
| Mapping structure | Page table | Segment table |
| Table entry | Maps a page to a frame, with relevant status/protection bits | Typically contains base and limit, plus possible protection/status information |
| Fragmentation | Can cause internal fragmentation; no external fragmentation in fixed-size frame allocation | Can cause external fragmentation |
| Protection | Can be applied at page level | Can be applied at segment level |
| Sharing | Pages can be shared | Logical segments can be shared |
| Programmer visibility | Usually transparent to the programmer | Reflects logical program units conceptually |
| Compaction | Not needed to manage fixed-size frames | May be used to address external fragmentation |

### Diagram: Paging

```text
Process divided into fixed-size pages

+--------+  Page 0
+--------+  Page 1
+--------+  Page 2
+--------+  Page 3

Each page fits into a same-sized physical frame.
```

### Diagram: Segmentation

```text
Process divided into logical, variable-sized segments

+----------------------+  Code
+------------+          Data
+------------------+    Heap
+--------+             Stack

Each segment may have a different size.
```

### Easy Way to Remember

- **Paging = fixed-size blocks.**
- **Segmentation = variable-size logical units.**

### Can a System Use Both?

Yes. Some memory-management designs combine segmentation and paging. A logical segment may be divided into pages, depending on the architecture and operating system.

## 7. Worked Comparison Example

Suppose a process contains:

- Code: 500 bytes
- Data: 180 bytes
- Stack: 120 bytes

### With Segmentation

The process has three logical segments of different sizes: 500, 180, and 120 bytes. Each segment needs a suitable physical memory region, and its base and limit are used for translation and bounds checking.

### With Paging

If the page size is 100 bytes, the code needs 5 pages, the data needs 2 pages, and the stack needs 2 pages. The final page for data and stack may not be fully used, resulting in internal fragmentation within those allocated pages.

This example illustrates the core distinction: segmentation follows logical units, while paging uses fixed-size blocks.

## 8. Advantages and Disadvantages — Quick Revision

### Advantages of Segmentation

1. Represents the logical organization of programs.
2. Supports protection at segment level.
3. Allows sharing of selected segments.
4. Supports segments of different sizes.
5. Allows logical units such as stack and heap to grow independently, subject to system limits.

### Disadvantages of Segmentation

1. Can cause external fragmentation.
2. Allocation and management of variable-sized regions are more complex.
3. Compaction may be required in some implementations.
4. Translation requires segment lookup and bounds checking.
5. A segment cannot be accessed beyond its defined limit.

---

## 9. Common Mistakes to Avoid

- **Mistake:** Treating pages and segments as the same thing.  
  **Correction:** Pages are fixed-size; segments are variable-size logical units.

- **Mistake:** Accepting `offset = limit` as valid.  
  **Correction:** The condition is `offset < limit`.

- **Mistake:** Calculating `base + offset` before validating the offset.  
  **Correction:** Check the segment number and limit first.

- **Mistake:** Saying segmentation has internal fragmentation as its defining problem.  
  **Correction:** Segmentation's classic fragmentation problem is external fragmentation.

- **Mistake:** Assuming all programs use exactly code, data, heap, and stack as four hardware-defined segments.  
  **Correction:** These are common conceptual units; actual layouts vary.

- Segmentation divides a process into **variable-sized logical units**.

- If invalid: the system raises an addressing/protection exception.
- Segmentation's classic fragmentation issue is **external fragmentation**.
- Paging uses **fixed-size pages**; segmentation uses **variable-size logical segments**.
